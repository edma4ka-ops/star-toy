# Бортовая прошивка: стабилизация, ручное управление, спасение

```
firmware/star_toy_rocket/star_toy_rocket.ino   прошивка (открыть в Arduino IDE)
firmware/config.h                              все настройки
```

Раньше в проекте было три разных куска: `flight/main.py` (курс по звезде),
`mcu/servo_loop.py` (контур на RP2040) и `recovery/` (парашют). Теперь есть
одна прошивка на плату, которая делает всё, кроме наведения.

## 1. Что входит и чего нет

| Есть | Нет (сознательно) |
|---|---|
| Ручное управление по RC | Удержание абсолютного курса по компасу/солнцу/звёздам |
| Стабилизация: гашение раскачки, удержание угла по стику | Полёт по точкам маршрута |
| Режим «удержание»: фиксируется то, что выставил пилот | Автоматический вывод на цель |
| Детект старта по перегрузке | Управление на спуске |
| Парашюты: дрог в апогее, основной купол по высоте | Телеметрия на землю (только лог в порт) |

Направление задаёт человек: углом пусковой и стиками. Ключевое отличие от
прежней версии `flight/main.py`: там курс приходил от оптического датчика
(солнце/звезда) и ракета держала его сама — это наведение, и в новой
прошивке его нет.

## 2. Фазы

```
IDLE ──арминг──► ARMED ──перегрузка 3 g──► BOOST ──выгорание──► COAST
                   │                          │
                   │                          └──апогей/таймер──► DEPLOYED ──► LANDED
                   └──снятие арминга/потеря RC──► IDLE
```

- **IDLE** — рули в нейтрали, замки закрыты, стики игнорируются.
- **ARMED** — только на столе и на направляющей: рули слушаются, парашюты
  заблокированы.
- **BOOST** — контур работает, парашюты взведены по времени.
- **COAST** — рули в нейтрали (после выгорания управление только мешает).
- **DEPLOYED** — дрог открыт, основной купол по высоте или по таймеру.
- **LANDED** — всё в нейтрали.

## 3. Распиновка (ESP32)

| Сигнал | Пин | Примечание |
|---|---|---|
| I2C SDA / SCL | 21 / 22 | MPU6050 + BMP280 на одной шине |
| PPM приёмника | 34 | только входные пины 34–39 |
| Рули: тангаж, рыскание, крен 1, крен 2 | 25, 26, 27, 32 | цифровые сервы |
| Замок дрога / основного купола | 33 / 5 | сервосброс, без пиротехники |
| Арминг | 4 | тумблер на 3.3 В, подтяжка 10 кОм к GND |
| Зуммер | 13 | |

Питание сервоприводов — отдельный BEC 5–6 В, ≥3 А. Земля общая с платой.

## 4. Режимы на тумблере (CH_MODE)

| Положение | Режим | Что делает |
|---|---|---|
| вниз | РУЧНОЙ | стик → угловая скорость, без выравнивания |
| центр | СТАБИЛИЗАЦИЯ | стик → угол до 20°, по умолчанию |
| вверх | УДЕРЖАНИЕ | запоминает текущее положение и держит его |

«Удержание» держит угол по интегрированию гироскопа. За 10–20 секунд полёта
уход — единицы градусов. Абсолютного курса нет: магнитометр на ракете
бесполезен из-за помех двигателя и сервоприводов.

## 5. Откуда коэффициенты

`KP 0.35`, `KD 0.08` — из прогонов `sim/run_sim.py` и `sim/size_canards.py`
(ракета D=75 мм, m=3 кг, рули 50 см², плечо 0.45 м). Для другой массы или
калибра коэффициенты пересчитываются в `sim/`, а не подбираются в полёте.

Правило из `docs/FINDINGS.md` остаётся в силе: рули должны быть сильнее
оперения, `S_рул · CN_δ · L_рул ≥ 1.5 · S_корп · CN_α · d_фокус`.
Ниже этого порога никакой `KP` не поможет.

## 6. Стендовые проверки по порядку

1. **Стики → рули** (режим РУЧНОЙ): все три оси, возврат в ноль без дребезга.
2. **Мёртвая зона**: стик в центре — `out` = 0 в логе.
3. **Реакция стабилизации**: наклонить корпус — рули возвращают, а не уводят.
   Если уводят, поменять знак у `angX`/`angY` в `updateAttitude`.
4. **Failsafe**: выключить передатчик — за 0.4 с рули в нейтрали, зуммер раз
   в секунду.
5. **Арминг**: без тумблера стики не двигают рулями вообще.
6. **Парашюты, «suck test»**: шланг со шприцем на статический штуцер,
   разрежение = набор высоты. Замки отсоединены, серво крутятся вхолостую.
   Три срабатывания подряд, в том числе по резервному таймеру (отключив
   барометр).
7. **Питание под нагрузкой**: все сервы одновременно, просадка BEC < 0.3 В.

## 7. Что проверить перед первым пуском

- Аккумулятор борта и BEC заряжены, запас по току.
- Арминг включается только на направляющей, в последнюю очередь.
- Механические стопоры рулей сняты.
- В зоне приземления нет людей: парашют неуправляем, ракета сносится ветром.
- Первый пуск — с балластом вместо полезной нагрузки и на минимальной тяге.

## 8. Чего в прошивке нет и почему

- Лог только в Serial. SD-карта или flash — следующий шаг, если нужен разбор
  без ноутбука.
- Нет барометрической компенсации плотности и нет калибровки давления
  на площадке в полёте: `groundPa` замеряется в `setup()` на столе, поэтому
  прошивку включают на месте пуска.
- Нет телеметрии: поиск ракеты — отдельная задача (GPS-трекер или маяк).

## 9. Сборка

Arduino IDE: открыть `firmware/star_toy_rocket/star_toy_rocket.ino`,
для ESP32 заменить библиотеку `Servo` на `ESP32Servo`, для BMP280 —
при желании заменить упрощённое чтение давления в `readPressurePa()`
на библиотеку Adafruit.

Прошивка не компилировалась в этой среде (нет тулчейна): первая сборка
и проверка регистров — на вашей плате.
